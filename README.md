# 금융 채용공고 아카이브

금융투자협회 모바일 채용 게시판의 공고를 개인용 SQLite 데이터베이스에 저장하고,
Streamlit 화면에서 검색하는 프로젝트입니다. 필요하면 SQLite의 전체 데이터를
MySQL로 복사할 수 있습니다.

## 현재 범위

- 금융투자협회 모바일 채용 목록 및 상세 본문 수집
- 동일 공고 중복 방지
- 최초 발견·최근 확인 시각 저장
- 본문이 바뀐 경우에만 수정 스냅샷 저장
- 규칙 기반 신입·인턴·경력 분류
- 회사 종류 1개와 직무 종류 최대 2개 자동 분류
- 키워드·회사·회사 종류·직무 종류·지원 대상·게시일 기간별 검색
- SQLite의 공고·수정 이력·수집 실행 기록을 MySQL로 복사

삭제 여부의 자동 판정과 첨부파일 다운로드는 아직 포함되지 않았습니다.

## 설치

PowerShell에서 프로젝트 폴더로 이동한 뒤 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## 수집

먼저 적은 페이지로 시험합니다.

```powershell
python -m job_archive.collect --pages 2 --delay 1.5
```

기본 데이터베이스 위치는 `data/jobs.sqlite3`입니다. 수집 대상 사이트의 이용약관과
robots.txt를 확인해야 합니다.

### 회사·직무 카테고리

회사 종류는 공고마다 하나를 저장합니다.

- 증권사, 자산운용사, 투자자문·일임, 은행, 보험사
- 신탁·부동산금융, 선물·중개, 평가·펀드서비스, 핀테크, 기타

직무 종류는 관련도 순서대로 최대 두 개를 `job_category_1`, `job_category_2`에
저장합니다. 제목에서 발견한 표현에는 본문보다 높은 가중치를 적용합니다.

- 퀀트·데이터, 리서치, 자산운용, 트레이딩, 리스크관리
- IB·기업금융, 영업·마케팅, 준법·법무, 운용지원·백오피스
- IT, 회계·재무, 경영지원, 기타

기존 SQLite 공고 전체를 새 기준으로 다시 분류하려면 다음 명령을 실행합니다.

```powershell
python -m job_archive.reclassify
```

## 검색 화면

```powershell
streamlit run src\job_archive\app.py
```

사이드바의 `게시일 시작일`과 `게시일 종료일`로 검색 기간을 지정할 수 있습니다.
시작일과 종료일을 모두 포함하며, 비워 둔 날짜에는 제한을 적용하지 않습니다.
기간을 지정하면 게시일이 없는 공고는 검색 결과에서 제외됩니다.

`상세 역량 공고만`은 같은 직무 구역에 구체적인 작업·분석 역량이 두 가지 이상
적힌 공고를, `포트폴리오 참고 공고만`은 구체적인 프로젝트 경험이나 코드·보고서
등 성과물 제출을 언급한 공고를 선별합니다. 두 항목을 함께 선택하면 하나라도
해당하는 공고를 찾습니다. 기존 게시일·직무·지원 대상 조건과 함께 적용됩니다.

선별 이유, 원문 근거, 성과물 제출 구분(필수·우대·선택/권장·미기재·경험 참고)을
표·상세 화면·CSV에 표시합니다. 규칙 기반 후보 선별이므로, 복수 직무 공고는
해당 직무의 신입 요건인지 원문을 확인해야 합니다. 금융상품 포트폴리오 표현과
명시적인 경력 필수 구역은 선별 근거에서 제외합니다. 별도 API 설정은 필요 없습니다.

프로젝트 증거 기반 프로필·공고 분석·포트폴리오 보완계획의 후속 구현 기준은
[1단계 설계 문서](docs/career_assistant_design.md)에 정리되어 있습니다.

## 프로젝트 프로필

사이드바의 `화면`에서 `프로젝트 프로필`을 선택합니다. 수집 DB가 없어도 사용할 수 있습니다.

1. 희망 직무·지역·시작 가능일과 기본 숙련도·학력·경험을 입력하고 `기본 프로필 저장`을 누릅니다.
2. `새 프로젝트 추가`에서 해결한 문제, 본인 구현 내용, 데이터·방법, 검증 결과와 한계를 입력합니다.
3. 증거 자료 표에 저장소·README·코드·노트북·보고서의 URL 또는 파일 경로를 적고 `프로젝트 저장`을 누릅니다.
4. 저장한 프로젝트를 선택해 수정할 수 있으며, 앱을 다시 열어도 내용과 자료 ID가 유지됩니다.

기본 프로필과 프로젝트는 각각 저장합니다. 새 자료와 내용이 바뀐 자료는 `미확인`으로
저장하며, 링크를 입력하는 것만으로 실제 구현을 확인하거나 숙련도를 올리지 않습니다.
사전에 없는 기술·역량은 프로젝트의 방법·분석 기법에 설명할 수 있습니다.

프로필은 `data/career/profile.json`에 저장되고 Git 추적에서 제외됩니다. 저장 중 파일
교체가 실패하면 이전 저장본을 유지합니다. `퀀트 적합도 모델` 화면은 저장한 기본 역량을
입력 기본값으로 불러옵니다. AI 분석 결과 가져오기는 후속 단계입니다.

## 공고 분석 자료와 추천 초안

먼저 `프로젝트 프로필`에서 기본 프로필을 저장한 뒤 공고 검색 화면으로 돌아옵니다.

1. 게시일·직무·지원 대상 등으로 검색한 뒤 `공고 분석 자료 내보내기`를 펼칩니다.
2. 검색 결과에서 공고 1~10개를 선택하고 분석 목적(학습 참고용/지원용), 기준일·시간대를 확인합니다.
3. 본문 글자 수·파일 크기와 목적별 추천 초안을 확인합니다.
4. `분석 묶음 생성`을 누른 뒤 `분석용 JSON 내려받기`로 받거나 로컬 사본 경로를 현재 대화에 알려주고 분석을 요청합니다.

JSON에는 저장된 프로필, 선택 공고의 전체 본문·원문 링크·게시일·마감일, 규칙 추출 요구사항
후보·근거·경고와 입력 해시를 담습니다. 본문을 자동으로 자르지 않으며 첨부파일은 이름·URL만
포함합니다. 요구 수준·직무 구분은 확인이 필요한 후보입니다. 공고 DB는 읽기 전용으로 조회합니다.

로컬 사본은 `data/career/requests/<bundle_id>.json`에 새 파일로 저장하며 Git에서 제외됩니다.
프로필·공고·선택 조건·기준일 등이 바뀌면 다시 생성해야 하며 이전 사본은 보존됩니다.
내보내기는 별도 AI API를 호출하지 않습니다.

추천 초안은 화면에서 별도로 계산합니다. `지원용`은 저장된 마감일 경과와 제목의 명시적
마감 표시를 분리하고, 희망 직무·신고 수준·필수 역량에 관련된 프로젝트 자료 후보를 비교합니다.
`학습 참고용`은 과거 공고도 유지하고 요구사항의 구체성과 목표 직무 관련성을 우선합니다.
재게시 그룹은 대표만 추천 순서에 포함하며 선택한 원본은 JSON에 모두 남깁니다.

높음/보통 등의 값은 검토 우선순위이며 합격확률이 아닙니다. 마감일 미경과도 현재 모집 중임을
뜻하지 않습니다. 미기재 역량은 미보유로 단정하지 않고, 링크나 검토 표시만으로 특정 작업을
증명했다고 처리하지 않습니다. 필수 자격의 최종 충족 여부와 작업별 증거 확인은 후속 대화
분석에서 다룹니다. 기존 0~120점 모델의 계산 규칙은 유지합니다.

## MySQL로 복사

MySQL 서버와 대상 데이터베이스는 미리 준비되어 있어야 합니다. 최초 한 번 MySQL에서
다음 데이터베이스를 생성합니다.

```sql
CREATE DATABASE finance_jobs
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

프로젝트 루트의 `.env`에 접속 정보를 입력하면 자동으로 읽습니다.

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=실제_비밀번호
MYSQL_DATABASE=finance_jobs
```

이후 아래 명령만 실행하면 됩니다. 터미널에서 직접 설정한 동일한 이름의 환경변수는
`.env` 값보다 우선합니다.

```powershell
python -m job_archive.export_mysql
```

기본 SQLite 경로는 `data/jobs.sqlite3`이며 `--sqlite`로 바꿀 수 있습니다. MySQL에는
`postings`, `posting_snapshots`, `crawl_runs` 테이블이 자동 생성됩니다. 회사·직무
카테고리 열도 함께 복사되며, 기존 MySQL `postings` 테이블에는 누락된 카테고리 열을
자동 추가합니다. 복사 명령은 한 트랜잭션으로 실행되고, 같은 `id`가 있으면 최신
SQLite 값으로 갱신합니다. MySQL에만 존재하는 행은 삭제하지 않습니다.

사용 가능한 전체 옵션은 다음과 같이 확인합니다.

```powershell
python -m job_archive.export_mysql --help
```

## 퀀트 채용공고 적합도 모델

검색 화면의 사이드바에서 `퀀트 적합도 모델`을 선택하면 지원자 스펙을 입력하고
최근 3년·5년 퀀트 공고의 적합도를 비교할 수 있습니다.

- 필수조건 최대 100점, 우대조건 최대 20점
- 필수조건이 없는 공고는 필수점수 100점과 `필수조건 미기재` 경고 표시
- 투자자산운용사와 기타 금융 자격증을 분리하고 기타 자격증은 최대 3개 반영
- 같은 회사·직무의 90일 이내 유사 재게시 공고 통합
- 퀀트 하위 직무 분류와 스펙 추가 시 평균 점수 상승 효과 제공

점수는 공고에 명시된 조건과 지원자 스펙의 일치도를 나타내며 합격확률이 아닙니다.

## 주요 데이터

- `posted_at`: 사이트에 표시된 게시일
- `first_seen_at`: 이 프로그램이 공고를 처음 발견한 시각
- `last_seen_at`: 마지막으로 공고 상세 페이지를 확인한 시각
- `last_changed_at`: 제목 또는 본문의 마지막 변경 감지 시각
- `audience`: 자동 분류 결과
- `manual_audience`: 사용자가 나중에 정정할 수 있는 분류값
- `company_category`: 회사 종류 한 개
- `job_category_1`: 가장 관련성이 높은 직무 종류
- `job_category_2`: 두 번째 직무 종류, 없으면 `NULL`

## 주요 파일

- `src/job_archive/collect.py`: 금융투자협회 공고 수집
- `src/job_archive/app.py`: Streamlit 검색 화면
- `src/job_archive/career_profile.py`: 프로젝트 증거 기반 프로필 검증·저장·기존 적합도 변환
- `src/job_archive/career_analysis.py`: 선택 공고·프로필·근거의 분석 묶음과 해시 생성·저장
- `src/job_archive/career_recommendation.py`: 목적별 규칙 기반 추천 초안과 근거·미확인 상태
- `src/job_archive/reclassify.py`: 기존 SQLite 공고 카테고리 재분류
- `src/job_archive/export_mysql.py`: SQLite 데이터를 MySQL로 복사
- `sql/schema.sql`: SQLite 테이블 정의
- `tests/test_export_mysql.py`: MySQL 복사 로직 테스트
